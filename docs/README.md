# Документация Home Hunter

Документы разделены по назначению. Сначала сверяйтесь с фактическими
описаниями архитектуры и сервисов, а затем переходите к инструкции нужного
источника или эксплуатационного сценария.

## Актуальные документы

| Документ | Назначение |
|---|---|
| [`ARCHITECTURE.md`](ARCHITECTURE.md) | Фактическая схема модулей, границы ответственности и ограничения. |
| [`SERVICES.md`](SERVICES.md) | Каталог сервисов `listings/services/` и их побочные эффекты. |
| [`DOCKER_ARCHITECTURE.md`](DOCKER_ARCHITECTURE.md) | Текущие Compose-сервисы, профили и systemd-процессы. |
| [`POLLING_METHODS.md`](POLLING_METHODS.md) | Добавление транспорта и правила расписания опросов. |
| [`AUTHORIZATION_CIAN_AVITO.md`](AUTHORIZATION_CIAN_AVITO.md) | Текущая схема профилей, cookies и сетевых маршрутов CIAN/Avito. |
| [`CIAN.md`](CIAN.md) | Эксплуатация CIAN, безопасный full scan и туннель. |
| [`LISTING_VISIBILITY_AND_GEO_ZONES.md`](LISTING_VISIBILITY_AND_GEO_ZONES.md) | Видимость объявлений, геокодирование и геозоны. |
| [`AVITO_SECONDARY_FILTER.md`](AVITO_SECONDARY_FILTER.md) | Текущие признаки вторичного рынка Avito и ограничения фильтра. |

`market_analysis/market_analysis_prompt.md` — рабочий промпт для подготовки
аналитического отчёта, а не описание программного контракта приложения.

## Правило актуальности

Если код и документ расходятся, сначала исправьте документ в том же изменении,
а затем добавьте запись в `CHANGELOG.md`. Документ, который описывает только
завершённый эксперимент или разовую проверку, должен иметь явную пометку
«Исторический» и не должен выглядеть как инструкция для production.
