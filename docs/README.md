# Документация Home Hunter

Документы разделены по назначению. Сначала сверяйтесь с фактическими
описаниями архитектуры и сервисов, а затем переходите к инструкции нужного
источника или эксплуатационного сценария.

## Правило актуальности

Если код и документ расходятся, сначала исправьте документ в том же изменении,
а затем добавьте запись в `CHANGELOG.md`. Документ, который описывает только
завершённый эксперимент или разовую проверку, должен иметь явную пометку
«Исторический» и не должен выглядеть как инструкция для production.

## Как поддерживать документацию

Параметры по умолчанию сверяйте с `.env.example` и `config/settings.py`, контейнеры — с `docker-compose.yml`, расписания — с `deploy/systemd`, контракты — с кодом и тестами. Назначения профилей и включённые timers зависят от установки: документация репозитория не подтверждает текущее состояние production.

[CHANGELOG](../CHANGELOG.md) хранит историю изменений, [AGENTS.md](../AGENTS.md) — обязательные правила разработки. Рабочий аналитический промпт задаёт требования к отдельному отчёту; его личные критерии не являются настройками приложения.
