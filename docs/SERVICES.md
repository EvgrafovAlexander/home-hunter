# Каталог сервисов Home Hunter

Документ описывает фактические границы файлов в `listings/services/`. Он нужен
перед изменением сервиса: сначала проверьте, подходит ли задача его текущей
ответственности, и только затем меняйте код.

`__init__.py` задаёт публичную границу сервисного пакета и не содержит доменной
логики.

## Сохранение и detail polling

| Модуль | Назначение | Изменяет данные / side effects |
|---|---|---|
| `spfa_audit.py` | Учёт вызовов SPFA и снимков cookies; отказ при невозможности аудита | `AvitoSpfaRequest`, `AvitoSpfaCookie` |
| `persistence.py` | Нормализация `NormalizedListing`, location rules, сохранение `Listing`, истории, snapshots и первичного решения Telegram | Общая ORM-транзакция для объявления и записи очереди |
| `avito_xlsx_import.py` | Проверка и ручной импорт XLSX Avito Parser | Сохраняет объявления через `persistence.py` |
| `detail_persistence.py` | Общие операции payload, недоступности и финализации опубликованного detail | Payload-модели, `Listing`, `ListingSnapshot`, detail state |
| `detail_polling.py` | Выбор кандидатов и общий последовательный цикл detail-опроса | Обновляет progress/state через переданные callbacks |
| `detail_progress.py` | Состояние циклов detail и список завершённых объявлений | ORM-транзакции над progress-моделями |
| `cian_detail_persistence.py` | Применение CIAN detail, адрес, геокодирование и source-specific snapshot | `Listing`, CIAN payload/state, snapshots, `PriceHistory`, Telegram score после commit |
| `avito_detail_persistence.py` | Применение Avito detail, фотографий и координат | `Listing`, Avito payload/state, snapshots |
| `scans.py` | Жизненный цикл Scan; накопление безопасности пакетов CIAN в checkpoint и деактивация только после безопасного цикла | `Scan`, объявления и snapshots |

Collectors получают данные, а persistence-сервисы сохраняют их. Detail-команды
не должны напрямую дублировать эти операции.

## Рынок, scoring и фильтры

| Модуль | Назначение | Граница |
|---|---|---|
| `market_trends.py` | Неизменяемые дневные срезы и недельные сравнения сегментов | Атомарное сохранение `MarketDailySnapshot`; без HTTP и сетевых вызовов |
| `market.py` | Единая политика сравнения цены, медианы и аналогов | Не формирует HTTP или Telegram-текст |
| `market_export.py` | Формирование XLSX-файла рыночной аналитики | Форматирует файл, но не определяет отдельную per-listing market policy |
| `scoring.py` | Объяснимый персональный Fit score | Не выполняет доставку уведомлений |
| `personal_filters.py` | Геозоны и жёсткие пользовательские фильтры | Чистые проверки и аннотация объектов |
| `listing_queries.py` | Queryset-фильтры, варианты фильтров и похожие объявления | Не рендерит шаблоны |
| `viewings.py` | Личные карточки, записи просмотров, привязки и доступ по владельцу | Транзакции ORM; запись подготовленных фото с очисткой при ошибке, удаление файлов после commit |
| `viewing_photos.py` | Проверка, ориентация и сжатие фото; lock общего media volume | Подготовка JPEG в памяти; без HTTP и ORM |
| `reviews.py` | Review queue, consideration и пользовательские решения | ORM-транзакции review-домена |
| `change_history.py` | Человекочитаемое описание изменений snapshots | Преобразование данных без внешних side effects |

`reviews.review_form_tag_groups()` готовит группы веб-формы без изменения кодов,
категорий в БД и исторических оценок. Telegram использует прежний
`review_tag_groups()`. Скрытие на `/reviews/` отправляется отдельной формой:
не создаёт оценку и не сохраняет заметки; глобальное скрытие доступно только
staff с непустой причиной до 255 символов. POST привязан к исходному объявлению:
если оно недоступно, обработчик возвращает 409, не выбирая другое.

Создание личной карточки с фотографиями выполняет `viewings.create_apartment()`: транзакция включает карточку, связь с объявлением и фото; media lock согласует запись с backup, а при ошибке новые файлы удаляются.

`viewings.save_apartment_with_photos()` также обновляет существующую карточку:
проверяет владельца и версию, добавляет фото без замены галереи и откатывает
сведения и новые файлы при ошибке.

`viewings.delete_apartment()` проверяет владельца и версию, удаляет личные записи
транзакционно и очищает файлы после commit. Связанные `Listing` не удаляются.

## Правила изменения

- HTTP-обработчики не добавляются в сервисы.
- Collector и parser не вызывают ORM-сервисы сохранения напрямую в обход
  orchestration-команды.
- Внешний side effect должен быть явно виден в описании модуля или публичной
  функции и по возможности выполняться после commit.
- Если ответственность сервиса меняется, обновите эту таблицу,
  `docs/ARCHITECTURE.md` и `CHANGELOG.md` в одном коммите.

## Ручная проверка Avito

`avito_manual_checks.py` выбирает очередь старых объявлений и атомарно сохраняет
доступность, ручную цену, пересчитанную цену за м², историю проверок и snapshots.
Проверка версии защищает от устаревшей формы; UUID операции исключает повторное
применение. Уведомления о цене вызываются через существующий механизм после commit.

## Исключения из рыночной статистики

`market_exclusions.py` задаёт единый допуск объявлений к рыночным расчётам,
идемпотентное исключение и возврат с историей авторов. Сеть не используется.
`unfinished_review_candidates()` выбирает точные пометки для разового переноса;
команда `exclude_unfinished_reviews` по умолчанию выводит кандидатов без записи.


`market_exclusions.eligible_market_queryset()` — общий допуск по действующим
исключениям для рыночных расчётов и рабочих очередей любых источников.
`listing_queries.filtered_listings()` по умолчанию убирает исключённые объявления;
`include_excluded=True` используется аналитикой для явного режима полного рынка.
Ручная проверка Avito, review queue и detail polling используют тот же допуск.
`detail_progress` считает объём цикла только по допущенным активным объявлениям;
`detail_polling` повторно проверяет пометку перед запросом каждой карточки.
Сохранение оценок и ручных проверок согласовано с исключением блокировкой Listing.
