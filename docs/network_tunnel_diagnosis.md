# Диагностика сетевого доступа к новому tunnel VPS

Дата проверки: 22 сентября 2026 года.

## Цель

Проверить, может ли стенд `188.120.244.43` подключиться к новому VPS
`185.161.251.49` для SSH SOCKS-туннеля, через который должны работать CIAN и
Avito.

## Что настроено на новом VPS

На `185.161.251.49` созданы:

- пользователь `cian-tunnel` с UID 10001;
- публичный ключ приложения Home Hunter;
- ограничение `AuthenticationMethods publickey`;
- `AllowTcpForwarding local`;
- `PermitOpen *:443 *:80`;
- `ForceCommand /bin/false`;
- SSH-служба на TCP/22.

Локальный firewall нового VPS разрешает входящий трафик. На старом стенде
исходящий трафик также разрешён.

## Результаты с ноутбука

- TCP/22 до `185.161.251.49` — доступен, порт открыт;
- маршрут traceroute доходит до `185.161.251.49`;
- ICMP ping не отвечает (это не является доказательством недоступности SSH);
- TCP/443 — таймаутит.

Следовательно, новый VPS доступен из интернета по SSH на TCP/22.

## Результаты со старого стенда

Со стороны `188.120.244.43` после замены адреса проверено подключение к
`185.161.251.49` на TCP/22. SSH-ключ приложения принят, SOCKS-туннель поднят,
healthcheck прошёл; внешний адрес через прокси — `185.161.251.49`.

Проверка выполнена после замены IP и подтверждает рабочую связку ключа,
ограниченного forwarding и production-контейнера.

## Сетевое правило

Для стабильной работы у провайдера должно быть разрешено:

```text
Источник: 188.120.244.43
Назначение: 185.161.251.49
Протокол: TCP
Порт: 22
```

Production уже переключён на:

```text
cian-tunnel@185.161.251.49
```
